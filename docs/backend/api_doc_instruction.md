# 【フロントエンジニア向け】Swagger API仕様書のクイックガイド
バックエンドのAPI仕様とテストができる「Swagger UI」を導入しました。開発の効率が劇的に上がるので、以下の手順に沿って活用してください。

## 1. 画面へのアクセス
バックエンドが起動している状態で、ブラウザから "https://localhost:8443/api" を開きます。

## 2. 画面の見方
- APIの確認: 画面を開くと "auth" などの機能ごとにAPIが並んでいます。調べたいAPI（例: "POST /auth/signin"）をクリックすると詳細が開きます。

- リクエストの確認: "Parameters" や "Request body" の欄を見ると、フロントから送信する必要があるデータのキー名や型がひと目でわかります。

- レスポンスの確認: "Responses" の欄を見ると、成功時（200や210）やエラー時（401や409）にバックエンドからどんな構造のJSONが返ってくるかが明記されています。

## 3. 画面から直接APIをテストする方法
Reactの画面がまだできていなくても、この仕様書から直接APIを叩いて生のレスポンスを確認できます。

1. 各APIの右側にある "Try it out" ボタンをクリックします。

1. 入力フォームのJSONの値を、テストしたいメールアドレスやパスワードに書き換えます。

1. "Execute" ボタンをクリックします。

1. すぐ下のエリアに、サーバーから返ってきた実際のステータスコードと、生のJSONレスポンスが表示されます。

## 4. 認証が必要なAPI（鍵マーク付き）のテスト手順
プロフィール取得など、APIの横に "鍵マーク" がついているものは、ログイン状態（トークン）がないとエラーになります。以下の手順で簡単にテストできます。

1. "POST /auth/signin" を使って、画面上でログインをテスト実行します。

1. 返ってきたレスポンスから "accessToken" の文字列（長い暗号文）をコピーします。

1. Swagger画面の右上にある、一番大きな "Authorize" ボタンをクリックします。

1. ポップアップの入力欄にコピーしたトークンを貼り付け、"Authorize" をクリックして閉じます。

1. これでログイン状態が保持され、鍵マークのついたAPIも通常通り "Execute" でテストできるようになります。

## 5. フロントの実装への活かし方
画面の一番下にある "Schemas" セクション、または各APIのレスポンス欄にある構造は、バックエンドの型定義（DTO）そのものです。データのキー名が "camelCase"（キャメルケース）か "snake_case"（スネークケース）か、"null" を許容するかどうかもすべてここに明記されています。これを見てReact側の "types.ts" などの型を組み立ててください。
